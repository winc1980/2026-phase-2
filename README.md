# Phase 2 進め方

- **学習用軽音タイムテーブル**を使う
- 所々、壊れて動かない箇所がある
- Issueを解決しながら技術の実装を学ぶ
- 自力で調べる。分からない時、何が分からないのか分からない時などは仲間で解決する、メンターに聞く
- [discord上のphase2チャンネル](https://discord.com/channels/970510596380430337/1537036239440576522)はphase2に関するあらゆることを話すことができます。「ここがわからない」といったメンターへの質問にとどまらず、「できた」「できない」「わからない」といった個人の感想も気軽にチャットして、気軽に話しましょう！！

## 諸注意・AIの利用

- ✕ コードを書かせる
- ✕ 不明点・エラーを解決させる、調査させる
- ○ エラー文や公式ドキュメントを読むために翻訳以外の機能のないサービスを使う
  - [Google翻訳](https://translate.google.com)
  - [Deepl翻訳](https://www.deepl.com/ja/translator)
- ※ 要するに、生成AIを使わないでほしいということです

# 課題（Issue）一覧

環境構築で`bun run setup`を実行すると、以下のIssueが自分のリポジトリに自動で作成されます。番号順に、`EASY`から取り組むのがおすすめです。

| # | 難易度 | 内容 |
| --- | --- | --- |
| 1 | EASY | 環境変数を設定しよう |
| 2 | EASY | トップページから各ページへの導線がない |
| 3 | NORMAL | 通知の表示が`useEffect`で囲われていない |
| 4 | NORMAL | フォーマッター・リンターが導入されていない |
| 5 | HARD | `application.tsx`のコンポーネントが肥大化している |
| 6 | HARD | データ取得が`useEffect`+`fetch`のままになっている |
| 7 | EXTREME | 早稲田メールアドレスのバリデーションがない |

各Issueの詳しい内容は、`gh issue view (番号)`かGitHub上の「Issues」タブから確認してください。
