# このドキュメントについて

このドキュメントには、学習用軽音タイムテーブルの環境構築の方法を記載する。学習を始める際や詰まった時に適宜確認すること。

ここでの目標は、次の状態になるまでです。

- 自分のGitHubアカウントにこのリポジトリのフォークがある
- 手元にクローンして`bun install`が終わっている
- `bun run setup`が正常に完了し、Issue・ラベル・ブランチ保護ルールが自分のリポジトリに用意されている

環境変数（`.env`）の設定やデータベースの初期化は、最初のIssueの中で扱います。ここでは行いません。

# Bun とは

Bun(バン)とは、Node.js/npmに代わる超高速なJavascript実行環境・パッケージマネージャーです。

> [!note]
> 実行環境とは、あるプログラミング言語をコンピュータで実行できるようにするソフトウェア群をいう。JavaScriptでは`Node.js`や`Bun`、`Deno`などがある。今回は高速な`Bun`を使う。

 <details>

 <summary>JavaScriptの実行環境について</summary>

JavaScriptは元来**ブラウザ上**で動作することを目的に開発された特殊なプログラミング言語である。しかし、後世になりバックエンドを含めてJavaScriptで一貫してシステムを構築できるよう、コンピュータ上で直接実行できる`Node.js`という実行環境が用意された。今は`Bun`が代替となりつつある。

 </details>

## GitHub CLI と jq

このプロジェクトのセットアップスクリプトは、GitHubの操作に`gh`コマンド（GitHub CLI）を、JSONの加工に`jq`コマンドを使う。

```sh
gh --version
```

```sh
jq --version
```

どちらもエラーになる場合は、[GitHub CLIのインストールガイド](https://github.com/cli/cli#installation)・各OSのパッケージマネージャーを参照してインストールする。

```sh
brew install jq
```

```powershell
winget install jqlang.jq
```

インストールできたら、GitHub CLIでログインする。

```sh
gh auth login
```

```sh
gh auth status
```

でログイン済みであることを確認する。

# STEP.3 クローンする

1. 上記画像を参考にGithub CLIコマンドをコピーする。
2. 実行する。

```sh
gh repo clone (your_username)/2026-phase-2
```

フォークしたリポジトリをクローンすると、講師側の元リポジトリが`upstream`という名前のリモートとして自動的に登録される。こうしておくことで、後から追加された課題や修正を自分のフォークに取り込めるようになる。念のため確認しておく。

```sh
 cd (your_path)/2026-phase-2
```

```sh
git remote -v
```

`origin`が自分のフォーク、`upstream`が講師側の元リポジトリを指していれば成功。

# STEP.5 セットアップスクリプトを実行する

```sh
bun run setup
```

このコマンドは、以降の学習で必要になる設定を自動でまとめて行う。実行すると、内部では次のようなことが行われる。

- `origin`・`upstream`のリモート設定が正しいかを確認する
- `upstream`の`main`ブランチの変更を、自分の`origin`の`main`ブランチに取り込む
- `main`ブランチに対して、Pull Requestを経由しないと変更できないようにするルール（ブランチ保護ルール）を設定する
- 学習会メンターをCollaboratorとして招待し、Pull Requestのレビュー担当（CODEOWNERS）として登録する
- 課題の難易度ラベル（EASY / NORMAL / HARD / EXTREME）を作成する
- Issue機能を有効化し、`issues/`ディレクトリの内容から自分のリポジトリにIssueを作成する

途中で失敗した場合は、表示されたエラーメッセージを読み、指示に従って対応してから再度実行する。**このコマンドは何度実行しても安全**なので、うまくいかないときはまず再実行してみるとよい。

> [!note]
> `bun run setup`は、以降このドキュメントで説明する`main`ブランチの保護ルールを自分のリポジトリに設定します。設定後は、`main`ブランチへ直接pushできなくなり、Pull Request経由でしか変更できなくなります。詳しくは[ワークショップの進め方.md](./ワークショップの進め方.md)を参照してください。

完了したら、GitHub上で自分のフォークの「Issues」タブを開き、Issueが作成されていることを確認する。

```sh
gh issue list
```

# STEP.6 動作確認する

```sh
bun run dev
```

ターミナルに表示されるURLをブラウザで開く。

> [!note]
> VSCodeの内部ブラウザではなく、Google Chromeを使用すると良い。`bun run dev`を実行したターミナル上で`o`を入力して`enter`すると、Google Chromeで開ける。

![chrome](./images/chrome.png)

このとき、`環境変数「DB_FILE_NAME」が設定されていません`のようなエラーが表示されて起動できないはずです。**これは正常な状態です。** 環境変数の用意は、最初のIssueで取り組みます。
