title: 環境変数を設定しよう
---

このプロジェクトを動かすには、環境変数（`.env`）を自分で用意する必要があります。

## 1 まずはエラーを確認する

このプロジェクトには`.env`がまだありません。試しにこのまま開発サーバを起動してみましょう。

```sh
bun run dev
```

`環境変数「DB_FILE_NAME」が設定されていません`のようなエラーが表示され、アプリが起動できないことを確認してください。

## 2 環境変数とは

環境変数とは何でしょうか？調べてみましょう。

このプロジェクトのルートには`.env.example`というファイルがあります。中を開くと、先ほどのエラーにも出てきた3つのキーが入っています。

- `DB_FILE_NAME`
- `JWT_SECRET`
- `SESSION_SECRET`

名前に`SECRET`と付いているものが何のために使われているのか、`app/sessions/`の中を覗いて確認してみましょう。

> [!warning]
> `SECRET`と付く値は名前の通り「秘密鍵」です。第三者に知られると、なりすましなど重大なセキュリティ事故につながるため、**絶対に漏洩させてはいけません**。
> git管理に含めたり、SNSやチャットに貼り付けたりしないよう注意しましょう。

## 3 .env.exampleから.envを作ろう

`.env.example`は、どんな環境変数が必要なのかをチームで共有するためのファイルです。
実際にアプリを動かすときに読み込まれるのは`.env.example`ではなく`.env`なので、これをコピーして`.env`を作成しましょう。

```sh
cp .env.example .env
```

`cp`コマンドは必須ではありません。エディタやファイラーで`.env.example`を複製・リネームしても構いません。

`JWT_SECRET`と`SESSION_SECRET`の値はまだ空になっています。次のステップで値を埋めていきます。

> [!note]
> `.env`は`.gitignore`に登録されているため、git管理下には入りません。各自の手元にだけ存在するファイルになります。

## 4 安全なシークレットキーを生成する

`JWT_SECRET`と`SESSION_SECRET`に、適当な文字列を入れてはいけません。
推測できてしまうような文字列だと、なりすましなどのリスクにつながります。

秘密鍵に複雑な意味やルールは必要ありません。**ランダムであること**と**十分な長さがあること**の2点さえ満たせば安全な値になります。

安全なランダム文字列を生成して、`.env`の各キーに設定しましょう。たとえば以下のようなコマンドで生成できます。

```sh
openssl rand -base64 32
```

`JWT_SECRET`と`SESSION_SECRET`にはそれぞれ別のランダム文字列を設定してください。

> [!note]
> 「なぜ推測できる文字列だと危ないのか」を考えてみてください。
> `SESSION_SECRET`はログイン状態（セッション）が本物かどうかを署名で検証するために使われています。

## 5 Pull Requestを作る

`.env`は`.gitignore`に登録されているため、このIssueで行った作業はPull Requestの差分（diff）には一切表示されません。ファイルの変更が無い、空のPull Requestになります。

そのままではレビュアーが作業内容を確認できないため、Pull Requestの説明文に、`bun run dev`で起動したトップページのスクリーンショットを貼り付けてください。画面が正常に表示されていれば、`.env`が正しく設定できている証拠になります。

> [!note]
> Pull Requestの説明欄は、画像をコピーした状態で直接貼り付ける（`Ctrl+V` / `Cmd+V`）か、ファイルをドラッグ&ドロップすることでスクリーンショットを添付できます。

## 6 達成条件

- [ ] `.env`が`.env.example`をコピーして作成されている
- [ ] `bun run dev`がエラーなく起動する
- [ ] `JWT_SECRET`と`SESSION_SECRET`が、`openssl rand -base64 32`などで生成したランダムな文字列に置き換えられている（初期値や推測可能な値のままでない）
- [ ] Pull Requestの説明文に、動作しているトップページのスクリーンショットが貼り付けられている
