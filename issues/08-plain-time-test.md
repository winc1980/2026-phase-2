---

`app/lib/plain-time.ts`の`PlainTime`は、時刻を表す小さなクラスです。
バリデーションや文字列との変換など、壊れると気づきにくいロジックを持っていますが、テストがありません。

同じ構造を持つ`PlainDate`にはすでにテストがあります。
`tests/lib/plain-date.test.ts`を読んで、どんな観点でテストが書かれているかを確認してから取り組んでください。

テストの実行環境（`bun test`・`tests/tsconfig.json`）は用意済みです。
`tests/lib/plain-time.test.ts`は空のファイルとして存在しているので、ここに書いていきましょう。

```sh
bun test
```

> [!note]
> `PlainDate`をそのまま真似すると間違える箇所がいくつかあります。
> `plain-time.ts`を実際に読み、`plain-date.ts`との**差分**に注意してください。

## 1 コンストラクタ

- [ ] `hour`・`minute`が、渡した値のまま保持される
- [ ] `hour`の下限・上限（有効な最小値と最大値）でエラーにならない
- [ ] `hour`が範囲外のとき、エラーメッセージ付きで失敗する
- [ ] `minute`の下限・上限でエラーにならない
- [ ] `minute`が範囲外のとき、エラーメッセージ付きで失敗する

> [!note]
> `PlainDate`の`month`・`day`は1始まりで`> 12`という比較でしたが、`PlainTime`はどうなっているでしょうか。
> 「ちょうど境界の値」と「境界の1つ外側の値」を両方テストすると、比較演算子の間違いに気づけます。

## 2 serde.serialize

- [ ] `hour`と`minute`が期待した書式の文字列になる
- [ ] 1桁の値を渡したときの出力を確認する

> [!note]
> `PlainDate`は年を`padStart`でゼロ埋めしていました。`PlainTime`にゼロ埋めはあるでしょうか。
> 「こうあるべき」ではなく「今のコードがどう振る舞うか」を書いてください。

## 3 serde.deserialize

- [ ] 通常の文字列をパースし、`hour`・`minute`が正しく取り出される
- [ ] ゼロ埋めされた文字列をパースできる
- [ ] 書式が不正な文字列を渡すと、エラーメッセージ付きで失敗する
- [ ] 書式は正しいが値が範囲外の文字列を渡すと、コンストラクタのエラーが伝わってくる
- [ ] `serialize`した文字列を`deserialize`すると、元の値に戻る

> [!note]
> 不正な文字列は1つではなく、区切り文字が違うもの・要素が足りないもの・そもそも数字でないものなど、複数のパターンを試してください。

## 4 now

- [ ] 現在時刻から`hour`・`minute`が取り出される
- [ ] 取り出した値に余計な補正が加わっていない

> [!note]
> `PlainDate.now()`は`getMonth() + 1`という補正をしていました。`PlainTime.now()`にそれに当たるものはあるでしょうか。
>
> 実行するたびに結果が変わるテストは失敗したり成功したりして信用できません。
> `bun:test`の`setSystemTime`を使うと時刻を固定できます。テストの後始末も忘れずに。

## 5 達成条件

- [ ] `tests/lib/plain-time.test.ts`に、上記1〜4の観点のテストが書かれている
- [ ] `bun test`が全て成功する
- [ ] `bun run typecheck`が成功する
- [ ] `bun run check`で指摘が出ない

### 発展（任意）

- [ ] `deserialize`の正規表現は前後に余計な文字があっても一致してしまいます。`"あ12:34い"`のような文字列を渡すとどうなるか、テストで確かめてください
- [ ] その挙動が望ましくないと判断した場合、`plain-time.ts`側を修正し、テストが通ることを確認してください
